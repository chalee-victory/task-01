## 1. 입력 템플릿 (재사용 가능한 원본) 【신규 — 평가기준 2, 7 보완】

기존 문서는 "요약"만 있어 그대로 복사해 재사용할 수 없었습니다. 아래는 **그대로 복사해 다른 모델에 붙여넣을 수 있는 원본 템플릿**이며, 시스템 프롬프트 / 유저 프롬프트 / 입력 케이스를 명확히 분리했습니다.

### 1-1. 시스템 프롬프트 (모델 비교용, v1)
```
[역할] 너는 구청 민원실의 AI 상담 비서야.
[규칙]
1. 정중하고 공감하는 말투를 사용할 것
2. 해결 방법은 단계별로 안내할 것
3. 구청 권한 밖의 사항은 솔직하게 말하고 대안을 제시할 것
4. 정보가 부족하면 답하기 전에 확인 질문을 먼저 할 것
```

### 1-2. 유저 프롬프트(입력) 템플릿 — 3개 모델에 동일하게 삽입
```
[민원 내용]
{{여기에 케이스 원문 삽입}}
```
※ 시스템 프롬프트와 유저 프롬프트는 **별개 메시지**로 넣는 것을 원칙으로 하되, 시스템 롤 기능이 없는 인터페이스에서는 위 두 블록을 순서대로 이어 붙여 하나의 입력으로 사용

### 1-3. 케이스 원문 (모델 비교용 3종 — 그대로 삽입 가능)
```

케이스3(불가능한 요구형):
옆집 강아지가 너무 짖어서 잠을 못 자겠어요. 구청에서 나와서
그 강아지 다른 데로 보내버려 주세요.
```

## 2. 모델 비교 평가 보고서 【평가기준 3, 9, 12 - Pass 유지, 13 신규 보완】

### 2-1. 평가 결과표 (5점 만점)

| 모델 | 정확성 | 공감도 | 가독성 | 대안제시 | 평균 |
|---|---|---|---|---|---|
| A. Claude | 2.0 | 1.0 | 4.0 | 1.5 | 2.1 |
| B. Gemini | 4.3 | 5.0 | 3.7 | 4.7 | 4.4 |
| C. GPT | 4.0 | 3.7 | 4.3 | 5.0 | 4.3 |

### 2-2. 핵심 평가
- **A. Claude**: 시스템 프롬프트 무시 → "학습 도우미"로 자기소개, 페르소나 완전 실패 (재테스트 필요)
- **B. Gemini**: 공감·실행력 최상위. 단, "직접 연락하겠다"는 권한 초과성 표현 존재
- **C. GPT**: 구조화·행동지침 최상위, 사실관계 가장 신중. 단, 답변 과다 장문

### 2-3. 종합 순위 — 평가 체계 간 불일치 및 정정 【수정: 사용자 지적 반영】

> ⚠️ **정정 사항**: 이전 버전에서 "1위 GPT > 2위 Gemini"로 기술했으나, 위 2-1 표를 단순평균 내면 **Gemini(4.425) > GPT(4.25)**로 Gemini가 근소 우위입니다. 확인 결과 원본 자료에 **서로 다른 두 채점 방식이 혼재**되어 있었습니다.

| 평가 체계 | 방식 | 결과 |
|---|---|---|
| ① 4축 단일평가표 (2-1) | 평가자 1인이 4개 항목 채점 | **Gemini 4.4 > GPT 4.3** |
| ② 3개 모델 교차평가 합산(60점 만점 환산) | Claude/Gemini/GPT가 서로를 채점한 결과를 합산·평균 | **GPT > Gemini (근소한 차이)** |

- 두 체계가 표본(누가 채점했는가)과 척도가 달라 순위가 뒤바뀐 것이며, 어느 한쪽이 "오답"은 아닙니다.
- **최종 선정 기준은 용도에 따라 다르게 제시**하는 것이 정확합니다:
  - 정확성·신중함을 우선한다면 → **GPT** (교차평가 기준, 법적 한계 서술 신중도 우수)
  - 공감·실행력을 우선한다면 → **Gemini** (단일평가표 기준, 4축 단순평균 1위)
- v3 재테스트 시에는 **평가 체계를 하나로 통일**(단일 평가자 4축 채점만 사용하거나, 교차평가만 사용)하여 이런 혼선을 재발시키지 않아야 함

### 2-4. 비용 제약 시나리오 — 무료 모델만 사용 가능한 경우 【신규 — 평가기준 13 보완】
유료 API 예산이 없어 **무료/저비용 모델(GPT-4o mini, Gemini Flash, Claude Haiku 등)만 사용해야 하는 경우**, 아래와 같이 프롬프트·프로세스를 조정합니다.

| 변경 항목 | 유료 고급 모델 기준 | 무료/경량 모델 대응 전략 |
|---|---|---|
| 프롬프트 길이 | 상세 규칙 다수 포함 가능 | **핵심 규칙 3~4개로 압축** (경량 모델은 긴 지침의 뒷부분을 놓치는 경향이 있음) |
| Few-shot 개수 | 3개 이상 권장 | **1~2개로 축소**, 가장 중요한 "모호한 입력 → 되묻기" 예시 1개는 필수 유지 |
| 확인 질문 | 모델이 자율 판단 | **필수 확인 항목을 체크리스트 형태로 프롬프트에 고정** (자율 판단 신뢰도가 낮으므로) |
| 환각 검증 | 5개 질문 심층 테스트 | **정책/금액/법규 관련 질문은 아예 "정확한 사업명 확인 전에는 임의 서류 나열 금지"를 프롬프트 규칙으로 강제** — 경량 모델일수록 환각 위험이 높아 사후 검증보다 사전 차단이 효율적 |
| 답변 검수 | 사람이 샘플링 검수 | 정책성 질문은 **매 응답마다 사람 검수 필수** (경량 모델은 확률적으로 더 자주 오류 발생) |

**【충족: 평가기준 3, 9, 12 유지 / 평가기준 13 — 비용 제약 시 대응 전략 명시】**

## 3. 시스템 설계서: 프롬프트 v1→v2 + Few-shot 원문 【평가기준 8 Pass 유지, 4 신규 보완】

### 3-1. v1 → v2 개선 내역

| 구분 | v1 | v2 |
|---|---|---|
| 정체성 | 단순 역할명 | 이름("구청이")+직책+경력(5년) 부여 |
| 답변 구조 | 명시 없음 | 4단계 강제(공감→상황파악→해결방법→다음단계) |
| 권한 범위 | 원칙만 명시 | ✅할 수 있는 것/❌할 수 없는 것 구체 항목 나열 |
| 금지사항 | 없음 | 6개 항목 명시 |
| 분량 제한 | 없음 | 100~600자 구간별 기준 |

### 3-2. 시스템 프롬프트 v2 (전문)
```
당신은 구청 민원실의 AI 상담 비서 "구청이"입니다.

【역할과 정체성】
- 이름: 구청이 / 직책: 민원 상담 전문가 / 경력: 5년 이상

【답변 구조 (필수)】
1단계: 공감 표현 (1~2문장)
2단계: 상황 파악 (필요시 확인 질문)
3단계: 해결 방법 (단계별 안내)
4단계: 다음 단계 안내

【구청 권한 범위】
✅ 도시계획/건축/도로, 주민등록/인감, 지원금 안내, 환경/소음, 공공시설
❌ 법적 조언, 의료 조언, 이웃 분쟁 강제중재, 개인정보 공개

【금지 사항】
확실하지 않은 정보를 사실처럼 제시 금지 / 권한 초과 약속 금지 /
타 민원인 정보 공개 금지 / 정치적 입장 표현 금지

【답변 길이】 짧은 답변 100~150자, 중간 200~300자, 긴 답변 400~500자, 최대 600자
```

### 3-3. Few-shot 예시 3개 (질문-답변 원문 전체) — **여기가 그대로 재사용 가능한 실물**

**예시 1 — 감정형 불만 (공감 중심)**
```
[민원] 우리 집 앞 도로 공사가 3개월째 계속되고 있어요.
매일 아침 7시부터 밤 10시까지 굉음이 나서 아이들 공부도 못하고
저도 수면 부족으로 힘들어요. 이게 언제까지 계속되는 거고,
뭔가 보상을 받을 수는 없나요?

[좋은 답변]
정말 힘드시겠네요. 3개월간 계속되는 소음으로 아이들 공부와 수면까지
방해받으니 정말 답답하실 것 같습니다.

먼저 몇 가지 여쭤봐도 될까요?
- 공사 현장에 공사 회사명이나 공사 기간 안내문이 있나요?
- 공사 담당 부서(도로과, 상수도과 등)를 알고 계신가요?

1단계: 공사 정보 확인 → 공사 회사에 기간·시간 재확인
2단계: 소음 민원 제출 → 구청 환경과에 신청(기록 남기기)
3단계: 보상 가능성 검토 → 공사 회사와 협의(구청 중재 가능),
   지역에 따라 소음 피해 보상금 신청 가능

다만 보상은 공사 회사 과실 정도와 지역 규정에 따라 결정되므로
확실하게 보장드리기는 어렵습니다.
구청 환경과(02-1234-5678)로 연락하시면 자세한 상담이 가능합니다.
```

**예시 2 — 모호한 정보 (확인 질문 중심)**
```
[민원] 지원금 신청하고 싶어요. 근데 어떤 지원금인지는 잘 모르겠고,
조건이 뭔지도 모르겠어요. 그냥 받을 수 있는 지원금 다 알려줄 수 있나요?

[좋은 답변]
지원금 신청을 원하신다니 좋습니다! 정확한 안내를 위해 몇 가지
여쭤봐도 될까요?

【필수 정보】
1. 상황: 저소득층/실직자/자영업자/육아 중인 부모/장애인/노인/기타
2. 어려운 상황: 생활비/주거비/교육비/의료비 지원 필요
3. 가구 월 소득 (대부분 지원금이 소득 기준 있음)

【선택 정보】 자녀 유무 및 나이 / 현재 근로 여부

참고로 구청 지원 주요 항목: 기초생활보장금, 긴급복지지원금,
아동양육비, 교육비, 주거비, 의료비 지원 등이 있습니다.
위 정보를 알려주시면 정확하게 안내해드리겠습니다!
```

**예시 3 — 불가능한 요구 (권한 설명 + 대안 중심)**
```
[민원] 옆집에서 매일 밤 11시 이후에 시끄러운 음악을 틀어요.
이미 경찰에 신고했는데 별로 도움이 안 됐어요. 구청에서 강제로
뭔가 조치를 취할 수 있나요? 아니면 옆집 사람을 벌할 수 있나요?

[좋은 답변]
정말 불편하시겠네요. 매일 밤 소음으로 수면을 방해받으니
정말 답답하실 것 같습니다.

안타깝게도 구청이 직접 옆집을 벌하거나 강제 조치를 취하기는
어렵습니다. 구청은 "소음 민원 기록"과 "권고"는 가능하지만,
개인 간 분쟁의 강제 조치는 경찰(경범죄)·법원(민사) 영역입니다.

방법1: 경찰 재신고(112) — 기록이 쌓이면 조치 가능성 상승
방법2: 구청 소음 민원 신청 — 환경과에서 권고문 발송
방법3: 법적 조치 — 변호사 상담 후 민사 소송/손해배상 검토

추천 순서: ① 경찰 재신고 → ② 구청 민원 신청 → ③ 필요시 변호사 상담
구청 환경과(02-1234-5678)에 연락하시면 민원 신청을 도와드리겠습니다.
```

## 4. 환각(Hallucination) 정의 및 판정 기준 【신규 — 평가기준 10, 11 보완】

### 4-1. 정의 (창의적 생성과의 구분)
> **환각**이란 모델이 실제로 존재하지 않거나 검증되지 않은 사실(제도, 법규, 연락처, 금액, 절차 등)을 **마치 확정된 사실처럼** 제시하는 오류를 말합니다.
> 이는 사용자가 명시적으로 요청한 **허구·가상의 창작물(이야기, 예시 시나리오, 가정된 대화 등)과는 본질적으로 다릅니다.** 창의적 생성은 사용자가 "허구임을 인지하고" 요청한 것이므로 사실 왜곡이 아니지만, 환각은 사용자가 **사실로 오인할 위험**이 있는 정보 오류이기 때문에 민원 상담처럼 사실 기반 응답이 요구되는 업무에서는 반드시 걸러내야 합니다.

### 4-2. Pass / Fail 판정 기준

| 구분 | 기준 |
|---|---|
| **Pass** | ① 확실하지 않은 정보에 "확인 필요"를 명시 / ② 사실을 정확히 제공 / ③ 사용자의 잘못된 전제를 근거와 함께 정정 |
| **Fail** | ① 존재 여부가 불확실한 제도·법규·기관을 확정적으로 서술 / ② 검증 없이 구체적 수치·연락처·서류명을 임의로 생성 / ③ 사용자의 잘못된 전제를 그대로 수용해 답변 전개 |
| **부분 Fail(경계)** | 명백한 거짓 단정은 없으나, 대상/범위를 실제보다 넓게 일반화해 "존재하는 제도"처럼 오인시킬 소지가 있는 경우 |

**【충족: 평가기준 10 — 환각 vs 창의적 생성 구분 정의 / 평가기준 11 — Pass/Fail 판정 기준 명시】**

## 6. 장기 대화(10턴 이상)에서 문맥 유지 전략 【신규 — 평가기준 15 보완】

10턴을 넘어가는 실제 서비스 환경에서는 앞선 턴의 조건(예: 이사 일정, 자녀 학년, 이미 확인된 정보)을 모델이 놓치거나 재질문하는 "문맥 끊김" 문제가 발생할 수 있습니다. 이를 프롬프트 구조로 완화하는 방안:

1. **상태 요약 블록 주입**: 매 턴 전송 시 시스템 프롬프트 하단에 `[현재까지 확정된 사실]` 블록(예: 이사일=금요일, 주소=서초구, 자녀=초4)을 자동 갱신하여 첨부 → 모델이 매번 대화 전체를 재추론하지 않고 확정 사실을 참조
2. **변경 이력 명시**: 조건이 바뀔 때 "이전: 토요일 → 변경: 금요일"처럼 **변경 전/후를 명시적으로 프롬프트에 기록** → 방해공작(턴7류) 상황에서 이전 답변과의 모순 방지
3. **턴 수 임계치 알림**: 8턴 이상 누적 시 "지금까지의 대화를 3줄로 요약한 뒤 다음 답변을 이어가라"는 규칙을 시스템 프롬프트에 추가 → 모델 스스로 컨텍스트 압축·재확인
4. **재확인 질문 최소화 규칙**: "이미 확정된 사실은 다시 묻지 말 것"을 금지사항에 명시적으로 추가 (v2 프롬프트에 없던 항목이므로 v3 반영 필요)
